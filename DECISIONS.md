# DECISIONS.md

1. **Indexes.**Created a unique compound index on `attendance_logs(emp_code, date)` to prevent duplicate daily records and guarantee race safety; a unique index on `employees(emp_code)` for identity lookup; and indexes on `attendance_logs(date, status)`, `attendance_logs(department, date)`, and `employees(department, joined_on)` to support high-speed range queries and analytics. Considered secondary text search indexes but rejected them as exact field matching, regex anchoring, and range filters are sufficient.

2. **Punch-in race.** Two simultaneous punch-in requests hit the unique compound index `(emp_code, date)`. The first transaction succeeds and returns `201 Created`. The second transaction violates the unique index constraint, raising PyMongo's `DuplicateKeyError`, which is caught and cleanly translated into an HTTP `409 Conflict` response.
3. **Ties.** Used MongoDB's window function `$denseRank` inside `$setWindowFields` to implement standard competition ranking. Tied employees share the same rank, and subsequent ranks skip numbers appropriately (e.g., `1, 2, 2, 4`). The `limit` filter is applied *after* ranking so that all tied employees at the cutoff rank are successfully returned, ordered by total late minutes descending then `emp_code` ascending.
4. **Headcount.** Department summary uses a left-outer lookup joining `employees` with `attendance_logs`, filtering employees whose `joined_on` is on or before the end of the period (R9). This ensures employees with zero attendance logs are accurately counted while excluding those who join later.
5. **100x data.** To scale for 100x data volume, we would introduce a read replica cluster for heavy analytical queries, shard the `attendance_logs` collection by `emp_code` or `date`, and utilize background worker queues (or materialized summary collections) to pre-calculate monthly and daily analytics asynchronously.
6. **Local API documentation.** Documented the Windows PowerShell and macOS/Linux startup flow in `README.md`, including dependency installation and the `uvicorn app.main:app --port 8000 --reload` command. The README links to `/health` for readiness checks, `/docs` for interactive Swagger testing, `/openapi.json` for the machine-readable contract, and `/redoc` for alternate reference documentation. The root path `/` is intentionally not documented as an API endpoint because it returns `404 Not Found`.
